# CLAUDE.md

## What this is

CCOS Meta Viewer is an unofficial web GUI for browsing data from the official CharaChorder Firmware Meta API (`https://charachorder.io/firmware/`). It lets developers pick a device/firmware version and inspect the resulting `meta.json` (keymaps, actions, etc.) without hand-crafting API calls, and also bundles a Swagger UI page for the same API. Not affiliated with CharaChorder.

## Tech stack

- Nx monorepo (single app: `apps/ccos-meta-viewer`), npm/yarn workspaces
- React 19 + TypeScript, Vite build/dev server, Vitest + Testing Library for tests
- MUI (`@mui/material`) + Tailwind CSS for styling, `@emotion` as MUI's style engine
- `react-router-dom` for routing, `@tanstack/react-query` for data fetching
- `ag-grid-react` for tabular data, `@uiw/react-json-view` for raw JSON display, `swagger-ui-react` for the Swagger page
- ESLint (flat config) + Prettier (`singleQuote: true`)

## Commands

Run from repo root; Nx resolves the single project automatically.

- Install: `npm install` (or `yarn install`) — lockfiles for both exist, CI uses `npm install`
- Dev server: `npm start` (runs `nx serve ccos-meta-viewer --port 4301`; underlying Vite default port is 4200)
- Build: `npx nx build ccos-meta-viewer` (prod build used by deploy: `npx nx build ccos-meta-viewer --prod`)
- Test: `npx nx test ccos-meta-viewer` (Vitest, jsdom environment)
- Lint: `npx nx lint ccos-meta-viewer` (`eslint .` in the app dir)
- Typecheck: `npx nx typecheck ccos-meta-viewer` (`tsc --build --emitDeclarationOnly`)
- Deploy: `npm run predeploy && npm run deploy` (builds prod, then publishes `apps/ccos-meta-viewer/dist` to GitHub Pages via `gh-pages`) — this is what `.github/workflows/` runs on push to `main`.

There are no root-level `test`/`lint`/`build` npm scripts; those targets come from Nx's inferred plugins (`@nx/vite`, `@nx/eslint`, `@nx/js/typescript` in `nx.json`), so always go through `nx <target> ccos-meta-viewer` or `npx nx run-many ...`.

## Structure

- `apps/ccos-meta-viewer/src/api.ts` — all backend calls; every request hits `https://charachorder.io/firmware/...` directly (no local backend/proxy)
- `apps/ccos-meta-viewer/src/model.ts`, `src/model/` — TypeScript types for the Meta API response shape (devices, versions, keymaps, actions)
- `apps/ccos-meta-viewer/src/component/` — presentational pieces (device/version/meta selects, ag-grid cell renderers, info dialog)
- `apps/ccos-meta-viewer/src/page/` — routed pages: `index-page.tsx` (main viewer) and `swagger-page.tsx` (Swagger UI)
- `apps/ccos-meta-viewer/src/swagger-dark/` — a third-party dark-theme CSS override for Swagger UI, not authored for this app
- `apps/ccos-meta-viewer/dist/` — committed build output (not gitignored the way you might expect elsewhere — check before assuming it's disposable)
- `apps/ccos-meta-viewer/src/tools/minify-icon-font.ts` — crawls every device/version's `actions.json` on the live Meta API plus a small static list (icons used directly in JSX, e.g. `changelog-view.tsx`) to find every Material Symbols icon name actually used, then subsets `material-symbols-rounded-latin-full-normal.woff2` down to just those glyphs. Run via `npm run minify-icon-font`.

## Gotchas

- `vite.config.ts` hardcodes `base: '/ccos-meta-viewer/'` for both dev and build, because the app is deployed under a GitHub Pages project path (`https://andy23512.github.io/ccos-meta-viewer`). Don't remove this base path when tweaking Vite config or local dev links will break relative to the deployed path assumption.
- `npm start` serves on port 4301, but `vite.config.ts` itself specifies dev server port 4200 and preview port 4300 — the port actually used depends on which command you run.
- The app has no backend of its own; it's a pure client calling the live `charachorder.io` Meta API, so anything you test locally depends on that external API's availability and CORS behavior.
- `error.log` at repo root is a leftover local git/gpg signing failure log, not app output — safe to ignore.
- The icon font actually loaded at runtime is `apps/ccos-meta-viewer/src/assets/material-symbols-rounded-latin-full-normal.min.woff2`, which is gitignored and generated by `npm run minify-icon-font` (see Structure above). `predeploy` runs it automatically, but a fresh clone needs it run once before `npm start` will show any icons. The full, committed `material-symbols-rounded-latin-full-normal.woff2` is the source font that gets subset — update that one (from Google Fonts) if a needed icon is missing from it, then re-run the script.
